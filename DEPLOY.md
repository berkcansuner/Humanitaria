# Deploy — Render (free tier, Docker)

One Docker web service runs the FastAPI API and serves the built Vue SPA (same
origin, so no CORS in the browser). Config lives in `render.yaml` + `Dockerfile`.

## Steps

1. **Render → New → Blueprint** and connect the GitHub repo
   `berkcansuner/Humanitaria`. Render reads `render.yaml` and creates the
   `humanitaria` web service.

2. **Set the secret env vars** when prompted (these are `sync:false`, never in
   the repo):
   - `DATABASE_URL` (Supabase Postgres session pooler URI; holds the app tables
     and the pgvector index)
   - `GEMINI_API_KEY`
   - `PINECONE_API_KEY` (reranker only, optional)
   - `RELIEFWEB_APPNAME`
   - `GOOGLE_CLIENT_ID`
   - `GOOGLE_CLIENT_SECRET`
   - `INGEST_TRIGGER_TOKEN` (shared secret for `POST /admin/ingest/cron`)

   `AUTH_SESSION_SECRET` is generated by Render automatically. The model settings
   use code defaults (chat/query `gemini-3.5-flash-lite`, reports
   `gemini-3.8-flash`, embedding 768) — set them only if yours differ.

   Enable the `vector` extension in Supabase (Database → Extensions → vector)
   before the first deploy; the app creates its tables on start.

3. **Deploy.** First build is a Docker build (frontend `npm ci`+build, then pip
   install) → ~5–10 min. Watch the build logs.

4. **Note the live URL.** If it is exactly `https://humanitaria.onrender.com`,
   you're set. If Render appended a suffix (name taken), update these env vars in
   the dashboard to the real URL and redeploy:
   `FRONTEND_URL`, `GOOGLE_REDIRECT_URI` (`<url>/auth/google/callback`), `CORS_ORIGINS`.

5. **Google Cloud Console** → APIs & Services → Credentials → your OAuth client →
   add to **Authorized redirect URIs**:
   `https://<your-url>/auth/google/callback`
   (Consent screen still in "testing"? add the tester's email under Test users.)

6. **Open the URL** → Sign up (email/password) or "Continue with Google" → chat.

7. **Scheduled ingest.** Add the same `INGEST_TRIGGER_TOKEN` value as a GitHub repo
   secret (Settings → Secrets and variables → Actions). The
   `.github/workflows/nightly-ingest.yml` workflow wakes the app and calls
   `POST /admin/ingest/cron` twice a day; it can also be started by hand from the
   Actions tab ("Run workflow").

## Free-tier caveats

- **Cold start.** Spins down after ~15 min idle; the next request takes ~30–60 s.
- **All data lives in Supabase Postgres** (users, conversations, reports and the
  pgvector index), so deploys and restarts lose nothing. Free tier: 500 MB database
  limit and the project pauses after 7 idle days (the scheduled ingest keeps it
  active). The index keeps 12 months of reports and at most 200 per country
  (`RETENTION_DAYS`, `RETENTION_PER_COUNTRY_CAP`) to stay under the limit. There is
  no in-process scheduler in production (`INGEST_SCHEDULE_HOURS=0`).
- **Gemini 503 ("high demand")** is transient/external; the chat route fast-fails
  with a "model busy" message instead of hanging.
